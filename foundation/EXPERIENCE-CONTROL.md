# Public / Private experience control

Jera uses one controlled `ExperienceModeControl` in the home header and post composer. It implements David's [Figma permissions-switch](https://www.figma.com/design/hMHHSwGpq3A26xosOspqWO/jera?node-id=69-457): Public globe first, Private eye.square second, a quiet capsule and a selected tile. Accessible labels and hover titles retain the two names. The component selects experience and post visibility; DID membership stays in Account → Private audience.

The component uses canonical daoUI Action interaction/focus behavior and semantic background/icon roles. The existing IconButton API has fixed 44px-or-larger geometry, toggle semantics and accent selection; it cannot express this 32px fine-pointer radio tile with its current API. The app-owned composition therefore retains radio semantics and canonical Action styling. Generated daoUI sources remain unchanged. The Figma's otherwise unbound 7px gap and 10px outer radius are explicit app-owned component length roles, outside generated token blocks.

Fine pointers match the 79×40 design with 32px tiles; coarse pointers use 44px targets, making the capsule 103×52 while retaining the glyph size. Both placements hug their content. The Figma glyph exports and hashes are documented in `app/assets/icons/experience-provenance.json`. The shapes are complete exports; runtime semantic tint supplies the state, and native hosts need no private-use font.

`idPrefix` distinguishes `header-experience` and composer `experience` so focus and test IDs never collide. Arrow keys move between choices; Home selects Public and End Private. A selection uses the existing account-scoped experience event/store and saved preference. New-post drafts remain separate by experience, public-parent reply text/context remain retained through explicit changes, and private-parent replies keep their fixed Private cue. A feed change clears only the inactive composing recipient context, so a previously opened private reply cannot prevent a later global Public selection; its stored reply draft remains available.

Normal browser review against disposable real Snapback storage covers header/composer synchronization, keyboard selection/focus, retained root drafts, a private fixture post/reply restriction, switching globally after leaving that reply, reload preference, fine-pointer geometry, coarse-pointer targets and 320px page width. Run the review with Bun 1.4.2 and `tests/experience-switch.browser.mjs` against the isolated fixture client on port3035. Review captures were opened at desktop and phone widths, including both composer placements. This is browser evidence; the disconnected iPhone has not received this UI change yet.
