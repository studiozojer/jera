# Jera composition preview

An isolated Exact preview for judging a quiet stream, focused composer and recognizable thread. The production sign-in/account app at `../app/` is unchanged. The Public/Private · Preview cue and sample conversation label distinguish the fixtures from live operator work. The reusable Experience control in the composer changes the whole app context; see [EXPERIENCE.md](EXPERIENCE.md) for its snapshot/event API, data projection, draft/return rules and presentation seam.

Each route has one viewport-wide scroll region, including the desktop margins. Finite desktop threads close immediately beneath their last post with a bottom border and the canonical 32px corner radius. Writing-button clearance and safe-area space sit outside that outline; short conversations do not stretch their frame to the viewport bottom. Mobile threads retain their edge-to-edge expression. Each destination has a sticky header above its content: the stream retains Jera, Preview and the account avatar; a thread replaces those with Back and Thread. The thread title no longer occupies a second row inside the reading frame. A single outlined plus button opens Write from the bottom right, layered above the full-height scrolling content. Clearance is inside the end of the scrolling content, so the last post can move above the button without creating a permanent bottom strip. On desktop, a noninteractive corner cap attached to the sticky header paints the stationary rounded top edge. The centered content column carries the side borders and grows with its posts; it has no separate constrained scroller. Posts pass behind the header and its cap; author and timestamp share a line, and the body aligns beneath them. Below 704px, the stream and thread become edge-to-edge reading surfaces with full-width separators, 16px horizontal post insets and 12px vertical post spacing from daoUI. The header uses a smaller rendering of the same wordmark and the floating writing control is 48px, versus 64px on desktop. Its add symbol uses daoUI’s 24px icon size independently of reading-text scaling. The button allows for the bottom safe area; the feed continues beneath it. At enlarged text sizes, the avatar and content can wrap into separate rows; the type ramp is not reduced to force a fit. The fixture set contains 40 root posts and 20 replies, mixing short notes, longer paragraphs, lists, symbols and conversations. It is a finite scrolling specimen for judging an eventual infinite feed; pagination and virtualization are not implemented. Read a conversation, write a new post, or reply in a thread. Cancel retains the relevant draft; new-post and per-post reply drafts remain separate in each experience. Mode changes restore the corresponding draft without transferring text, retain the mounted composer and normalize its changed return path to the selected-mode feed. The composer uses the caret and text selection without a surrounding focus ring, following David’s preference for a quieter writing surface. Exact Unicode text is retained. New root posts appear newest-first in each experience’s feed; replies remain oldest-first within their conversation. Posts, replies and drafts live only for the mounted preview and reset on reload. All sample messages are authored fixtures, including those attributed to operator names; typing an @mention does not call an operator. Each post has an ellipsis menu with Copy text and a heart/comment/repost/send toolbar. Comment opens the conversation from the feed and opens the reply composer from a thread. Positive comment counts reflect direct replies to that post. Heart, repost and send are disabled placeholders, with no fabricated engagement counts. The four action glyphs use the canonical Whyte/sm text size (1rem, normally 16px), independently of their minimum 44px targets. Enabled reply/menu actions use a pointer cursor, bg.hover feedback and bg.pressed feedback; disabled placeholders use the default cursor and receive no hover treatment.


Thread conversations distinguish the original root from each reply’s immediate parent. The focused post spans the reading column; direct replies sit beneath it, with one child preview connected beside the avatars. A deeper continuation opens as a focused conversation through Show replies; multiple child branches use Show all replies. Indentation stays at one preview level. Back preserves the previous conversation and its scroll position; a focused reply also links to its parent. Every comment action targets its own post. The composer shows that recipient and a three-line excerpt, and posting reveals the new reply under the selected recipient without reviving the completed composer. No sorting/activity controls are introduced. `thread.contract` owns this Jera-specific composition rather than adding conversation data or navigation to daoUI.

## Run and review

Use the repository's pinned Exact submodule and Bun 1.4.2. Set `BUN` to that binary if the default Bun is older. From this directory, run `bun exact.mjs web --port 3034` for the interactive preview, and `bun exact.mjs verify` for the browser workflow/layout pass. The app has a separate identity, no network/auth/storage grants, and requires no backend or production credentials. Its only data-module sources read/change app-local experience context; the typed event boundary has no network transport.

Review the stream, composing, cancel/reopen and post/reply path at phone and desktop widths. The current mobile pass was exercised at 320, 375, 390 and 430px, the frame boundary at 704px, tablet width 768px and desktop width 1280px. The viewport fact changes presentation on the same routes as the window resizes; it does not create separate mobile navigation. Inspect the ordinary and enlarged text results, not just the passing interactions. Direct normal-browser checks cover left/right margin wheels, PageDown, Tab focus at normal and 53px root text size, cap/Write stability, mobile resizing and Back restoring the feed offset. Fifteen browser scenarios cover existing writing/navigation and experience-specific draft separation, feed filtering, post ownership and changed reply return paths. Five unit tests cover snapshots, ordered events, no-ops, late readers, unsubscription, reentrant notifications, invalid input and observer failure isolation. Against the running preview, `node scripts/review-experience.cjs` checks actual public/private canvas colors, radio targets and keyboard focus, retained editor identity, draft restoration, page widths, header/mask/Write consistency, browser Back and the posted result; `node scripts/review-threading.cjs` remains the focused threading review. Both accept `JERA_PREVIEW_URL` and `PLAYWRIGHT_MODULE`. Geometry findings remain unsuppressed: the latest full pass records four ordinary-size intersections involving floating controls, plus thirty-three enlarged-text intersections involving sticky/floating chrome across the expanded workflow set. This is not a layout-clean report; the supplemental Lean comparison is unavailable. Physical-device keyboard/IME, safe-area paint, sheet gestures and assistive-technology behavior remain separate work. Do not run the SDK-wide prove matrix. The actual Snapback post/independent-operator reply proof remains to be implemented after composition calibration; this preview does not settle thread audience or operator runtime architecture.

## Design ownership

`dao.contract` is an initial Exact expression of daoUI's named type ramp, spacing, radii and touch target, and `app.tamber` retains the existing Jera mapping of canonical colors plus David's approved gold action accent. Scalable text insets accommodate the browser font ink while retaining canonical font size and leading. `fixtures.contract` owns the finite authored sample set. `post.contract` owns author anatomy, post options, the action toolbar and the preview record shape; `thread.contract` composes the focused post, reply branches and continuation disclosure; `chrome.contract` owns shared app chrome and the decorative corner cap. The stream and thread headers report their rendered heights independently through Exact’s resize event; post controls use that height as a native scroll margin so keyboard focus clears it after text-size or viewport changes. The desktop outlined column, mobile edge-to-edge expression and floating Write entry adapt David’s supplied Threads screenshots; his latest correction specifies bottom right and a true overlay rather than a reserved bottom row; the sidebar is omitted and the existing account-avatar position is retained. This deliberately moves the writing entry away from the reading family’s earlier header recommendation for this consumer. The canonical daoUI Exact sources/assets from checkpoint 804b73aa are now copied under dao/ and assets/dao/, using the committed consumer checkpoint 64e209d and its receipt. Composer buttons, post actions, menus, Back and Write consume the shared Button/IconButton/Menu families. `python3 dao/check.py` verifies all 106 copied files and generated Tamber blocks without a sibling checkout. The Experience control is a Jera-specific controlled radio composition using canonical Action behavior and the 44px minimum, so its visual expression can be tested without moving app context/routing into daoUI. The comment bubble and paper-plane SVGs are original local outlines mapped through app.tamber icon roles, with SF Symbol mappings for Apple; the remaining icons use Exact’s shared symbol roles. `provenance.json` records source revisions, copied font/brand hashes and deliberate local expression. Browser review exercises the menu opening and closing; the Exact JS agent suppresses copyText clipboard writes, so it does not verify the system clipboard.

The current product direction, original conversation, Albers process reflection and design strata live in the composed commons under `projects/jera/` and `projects/daoui/`. Discover the actual composition binding rather than assuming a worktree resolves the main checkout's sibling paths. Keep future UI corrections connected to that intent and return reusable changes to daoUI when use warrants it.

The standing lexicon-shaped UI north star is recorded in the root and foundation entry instructions and `../PRODUCT.md`. Experience mode remains distinct from lexicon identity. Public/private rendering shares one base composition and varies only the authored canvas via `experience.canvas` in this first experiment. The pinned SDK does not allow app-axis variation of its host Canvas/background roles; native-owned safe-area adaptation remains future work. No production application, ACL or ATproto publication changes are implied. The earlier phone-promotion work under `../app/` remains unfinished and separate.
