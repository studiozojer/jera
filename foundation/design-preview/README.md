# Jera composition preview

An isolated Exact preview for judging a quiet stream, focused composer and recognizable thread. The production sign-in/account app at `../app/` is unchanged. The Preview label and sample conversation label distinguish the fixtures from live operator work.

The shared header keeps the account entry in the same place across the stream and thread. A single outlined plus button opens Write from the bottom left, outside the scrolling content. On desktop, the central reading column has one rounded outline with dividers between posts; author and timestamp share a line, and the body aligns beneath them. Below 704px, the stream and thread become edge-to-edge reading surfaces with full-width separators, 16px horizontal post insets and 12px vertical post spacing from daoUI. The header uses a smaller rendering of the same wordmark and the bottom-left writing control becomes 48px at ordinary text size. The reading surface keeps clear of that control and allows for browser safe-area insets. At enlarged text sizes, the avatar and content can wrap into separate rows; the type ramp is not reduced to force a fit. The fixture set contains 40 root posts and 20 replies, mixing short notes, longer paragraphs, lists, symbols and conversations. It is a finite scrolling specimen for judging an eventual infinite feed; pagination and virtualization are not implemented. Read a conversation, write a new post, or reply in a thread. Cancel retains the relevant draft; new-post and per-thread reply drafts remain separate. The composer uses the caret and text selection without a surrounding focus ring, following David’s preference for a quieter writing surface. Exact Unicode text is retained. Posts, replies and drafts live only for the mounted preview and reset on reload. All sample messages are authored fixtures, including those attributed to operator names; typing an @mention does not call an operator. Each post has an ellipsis menu with Copy text and a heart/comment/repost/send toolbar. Comment opens the conversation from the feed and opens the reply composer from a thread. Positive comment counts reflect the fixture replies. Heart, repost and send are disabled placeholders, with no fabricated engagement counts.

## Run and review

Use the repository's pinned Exact submodule and Bun 1.4.2. Set `BUN` to that binary if the default Bun is older. From this directory, run `bun exact.mjs web --port 3034` for the interactive preview, and `bun exact.mjs verify` for the browser workflow/layout pass. The app has a separate identity, no capabilities or external data sources, and requires no backend or production credentials.

Review the stream, composing, cancel/reopen and post/reply path at phone and desktop widths. The current mobile pass was exercised at 320, 375, 390 and 430px, the frame boundary at 704px, tablet width 768px and desktop width 1280px. The viewport fact changes presentation on the same routes as the window resizes; it does not create separate mobile navigation. Inspect the ordinary and enlarged text results, not just the passing interactions. Native keyboard, IME, safe-area paint, sheet gestures, assistive focus and physical-device feel remain separate work. Do not run the SDK-wide prove matrix. The actual Snapback post/independent-operator reply proof remains to be implemented after composition calibration; this preview does not settle thread audience or operator runtime architecture.
