## Backend-connected mobile promotion — November 5

David requested preparing the calibrated interface for the real mobile app. Posts and replies sync to the existing Snapback backend at https://snapback.jera.ink; they are not device-only and are not published to ATproto. Public means readable by signed-in Jera accounts. Private uses a DID audience with read or reply capability; the account UI initially adds read-and-reply members. Private roots and private replies to public parents use the author’s private audience. Descendants of private posts inherit that same audience, and cannot become public or substitute another audience. Removing membership affects existing and future server reads, including descendants authored by the removed member.

Unpublished drafts are owner-only cloud records, independent of posted audiences. Each device has a versioned branch plus an account/origin-scoped local recovery journal. Local input persists without waiting for the network; debounced and foreground periodic sync copy it privately to Snapback. A fresh device can recover the latest branch for its composing context. Delayed saves cannot resurrect a posted draft: publication and the cloud draft tombstone share a transaction. A lost post response seals the exact intent/bytes/audience and retries the same write; the UI verifies the current authoritative record before claiming it was sent. Draft input and pending intents remain recoverable locally and sync when the app is online/foregrounded again. Existing OAuth/DID identity, old memory records and native signing identity remain in place. There are no seeded users/messages in the authenticated UI and no automatic task creation from posting. A real operator scheduler/reply remains separate work; shared authenticated post operations are available to independently authorized operator accounts.

## Settled requirements

- Jera is an ATproto application. People sign in with an existing ATproto account; its verified DID is their canonical identity. A separate Jera email/password account is not an accepted substitute. Internal backend principals and sessions must be bound to that identity.
- Preserve scattered ideas, original wording, exact Unicode forms and provenance, including fragments that never become executable work. Derived interpretations must retain attribution and links to their sources.
- Multiple armillaries can coexist. Shared modules have human and operator participants. A later local coding harness must be able to query the work without depending on one model or operator runtime.
- The intended interaction is social: threads, operator mentions and attributable responses. First prove the simple posting/reply loop described above. Organizing ideas into an armillary for later action remains a subsequent direction. A claimable queue alone is not an operating AI collaborator.
- Exact and Snapback are selected infrastructure. Their examples do not decide Jera's account model, public-record ownership, privacy, or user journey. Snapback is not an ATproto PDS.
- Unicode tagging is core to the direction. Astrology is an optional module. Discovery-feed ranking and a large capability framework are deferred.
